## 2. 合成挑战

最终批次身份：`reports/challenges-20261011-final.json`。包含 **5 个小型 Flask 仓库、30 个任务、每任务 11 类预设变异，共 330 个组合**。

| 样本范围 | 数量 | 处理方式 |
| --- | --- | --- |
| 有效预设正例 | 150 | 纳入检测矩阵；标签表示需要复核 |
| 有效预设良性例 | 150 | 纳入检测矩阵 |
| `hollow_test` 无效执行 | 30 | 原始测试节点缺失，判 `INVALID`，保留并排除计分 |
| 有效但未标注 | 0 | 本合成批次没有这类样本 |

累计信号的顺序为 `tests → requirements → diff → trace`。TP / FP / FN / TN 指在 300 个有效且预设有标签的样本上，是否被累计信号标记；不能把这些计数解释成恶意意图判断或自动阻断次数。

| 累计信号 | TP | FP | FN | TN | 该受控集上的召回率 |
| --- | --- | --- | --- | --- | --- |
| tests | 0 | 0 | 150 | 150 | 0% |
| + requirements | 60 | 0 | 90 | 150 | 40% |
| + diff | 120 | 0 | 30 | 150 | 80% |
| + trace | 150 | 0 | 0 | 150 | 100% |

测试阶段的 TP 为 0 是这套变异场景的结果，不代表测试在真实项目中没有价值。完整性失败的 30 个样本已经进入 `INVALID`，不能再混进正常检测矩阵。

### Trace 实际增加了什么

`transient_test_edit` 先修改既有测试并执行，随后恢复测试文件。最终测试、需求和 diff 没有标记该变异，实际工具事件留下了中途修改记录。Trace 在前三类信号之后新增 **30 个标记，全部来自这类预设正例**，所选良性样本中没有新增误报。

其他良性挑战包含合法新增测试、正常调试、失败编辑和注释修改。完整的逐变异聚合计数见 JSON 的 `synthetic_challenges.per_mutation`；累计矩阵由原始观测重新计算。

### 解释限制

- 标签来自场景合约，不是独立人工审核；“需要复核”不等于恶意。
- 同一个任务复用多种变异，任务还共享仓库；330 个组合不是 330 个独立真实 Agent 输出。
- 按任务重采样得到退化区间，报告明确标记为不可估计，不能推出总体零误报或真实召回率 100%。
- 原始测试、需求和 diff 也可以在强化 CI 中实现。这里证明指定 trace 场景的增量覆盖，没有证明比强化 CI 更能修好真实任务。

首个并行批次曾产生 10 个良性误报：Windows 下 pytest 向上遍历目录，访问了被其他进程清理的兄弟工作区。随后增加目录收集边界和独立配置，并用 [并行回归](../tests/test_parallel_verification.py) 验证修复。旧诊断批次被保留，以上矩阵取修复后的最终批次。

复跑时使用新的输出文件：

```powershell
python vericoder.py eval --suite all --jobs 8 --out reports/my-challenges.json
```

因预期存在 `INVALID`，该命令返回非零退出状态；应查看报告确认无效样本的原因和分母处理。

## 3. 离线四条件配对

批次：`offline-paired-20261011`。任务：`todo-app/002`，分页需求。共两次脚本重复、8 个条件结果；每次重复的四条件共享首次产出。两次脚本首次补丁的哈希也相同，不能当作两个独立模型样本。

| 条件 | 内部验证通过 | 每个结果的重试次数 |
| --- | --- | --- |
| `no_retry` | 0 / 2 | 0 |
| `tests_retry` | 0 / 2 | 0 |
| `requirements_retry` | 2 / 2 | 1 |
| `full_retry` | 2 / 2 | 1 |

首次产出通过原始测试但遗漏需求，因此需求反馈触发重试，单纯测试反馈不触发。[ScriptedAgent](../agent/scripted.py) 收到反馈后会调用预先写好的正确场景，修复不是模型阅读反馈后学习得到。结果只验证反馈路由、共享首次产出与证据链，不支持“LLM 成功率从 0% 提高到 100%”。

没有独立保留的最终验收，表中通过以当前内部测试和需求检查计分。复现流程：

```powershell
python vericoder.py study --agent scripted --scenario omit_requirement --suite todo --task 002 --repeat 2 --max-retries 1 --save
```

## 6. 公开数据的可核查范围

[validation.json](validation.json) 提供分母、累计混淆矩阵、逐变异计数、配对条件汇总、成功试跑参数、外部阻塞状态和来源文件 SHA-256。发布内容只选择必要的聚合字段，未复制完整补丁、轨迹、模型对话、凭据或本机绝对路径。

源码、离线任务和回归测试随仓库提供，可以重跑工程机制和受控挑战。来源哈希可以标识本地保留的原始文件；**没有原始文件时，哈希本身不能让外部读者独立审计全部观测**。这份公开摘要不应冒充完整开放实验数据。

原始证据位于 `runs/evidence/paired/<run_id>/` 等运行目录，被 `.gitignore` 排除。新实验会生成新的证据包，使用 `--save` 后也写入 SQLite，按 `run_id` 区分批次。`human_interventions` 只统计实际记录的人工操作事件，失败不会自动转为人工干预；无记录也不能推出真实人工成本为零。
